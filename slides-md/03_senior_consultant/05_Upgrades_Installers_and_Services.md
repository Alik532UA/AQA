## Тестування інсталяторів та розгортання

Інсталятор — це перша точка контакту мерчанта з додатком. Помилка інсталяції блокує 100% користувачів.

### Специфіка автоматизації інсталяторів:

- **Silent / Unattended Install:** тестування ключів тихого встановлення (`/S`, `/qn`, `/VERYSILENT`) з перевіркою Exit Code `0`.

- **Перевірка структури файлової системи:** цілісність бінарників у `%LocalAppData%\Programs` або `%ProgramFiles%`.

- **Валідація цифрового підпису:** перевірка сертифіката через `signtool.exe verify /pa` для запобігання попередженням Windows Defender / SmartScreen.

- **Перевірка системного реєстру:** коректність ключів деінсталяції у `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall`.

- **Асоціації протоколів (Deep Links):** реєстрація кастомних протоколів (наприклад, `merchantapp://pay`).

## Життєвий цикл оновлень (App Upgrades) та фонові служби

### Тестування оновлення версії (N → N+1):

**1. Збереження сесії та даних (State Persistence):** встановлення версії N → авторизація мерчанта, збереження локальної бази (SQLite / IndexedDB) → запуск автооновлення на N+1 → перевірка збереження сесії без повторного логіну.

**2. Блокування файлів (File Locks):** оновлення додатку у фоні, поки мерчант працює; валідація механізму Windows Restart Manager.

**3. Rollback (Відкат):** аварійне завершення оновлення не повинно призводити до неробочого стану програми.

### Тестування Windows Services:

Перевірка статусу через PowerShell (`Get-Service`) або C# `ServiceController`: запуск служби, авторестарт при збоях, робота під LocalSystem обліковим записом без витоків пам'яті.
