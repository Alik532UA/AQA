## Виклики Per-Monitor DPI та Multi-Display у Windows

Мерчанти часто використовують 2 монітори: основний екран каси (1080p @ 100%) та клієнтський дисплей (Touchscreen / 4K @ 150%). Це найчастіше джерело UI-багів.

### Критичні сценарії для автоматизації:

- **Переміщення вікна між моніторами з різним DPI:** перевірка, чи не розмивається інтерфейс Electron (DPI Awareness: Per-Monitor V2) та чи не спотворюються модальні вікна.

- **Віртуальні координати екрана:** лівий або верхній додатковий монітор має від'ємні координати `X/Y` у Windows API (Virtual Screen Bounds).

- **Мінімальні роздільні здатності (1366x768, 1280x800):** валідація появи коректних скролів та відсутності обрізання кнопок оплати.

- **Зміна орієнтації (Portrait vs Landscape):** актуально для планшетних POS на Windows 11.

## CI Virtual Machines vs Dedicated Test Machines

**CI Virtual Machines (Хмарні/Ефемерні ранери):**
• Призначення: 90% щоденних тестів (PR checks, Electron UI, API інтеграція, базові інсталятори).

• Конфігурація: фіксований віртуальний дисплей 1920x1080 @ 100% DPI. Забезпечує детермінованість і швидкість.

**Dedicated Test Machines (Виділені фізичні стенди):**
• Призначення: перевірка складних нативних сценаріїв, які неможливо заемулювати у віртуалці.

• Multi-Monitor стенди з різним фізичним DPI (100% + 150%).

• Фізичне торгове залізо: POS-термінали, сканери, чекові принтери через COM/USB.

• Валідація апаратного графічного прискорення (GPU Acceleration).
