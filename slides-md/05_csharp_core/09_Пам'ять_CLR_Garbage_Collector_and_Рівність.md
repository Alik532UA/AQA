# Пам'ять CLR, Garbage Collector & Рівність

> **Підтеми:** Покоління GC (0, 1, 2, LOH), Mark-Sweep-Compact, IDisposable vs Finalizer, == vs Equals & GetHashCode

**Категорія:** C# Core & Advanced (.NET)

---

## Пам'ять CLR, Робота GC & IDisposable

### Як працює Garbage Collector (GC):

GC в .NET автоматично керує керованою купою (Managed Heap). Фази збирання:

- **Mark:** починаючи від GC Roots (статичні поля, локальні змінні стеку), обходить граф і маркує живі об'єкти.

- **Sweep:** визначає блоки пам'яті з мертвими (недосяжними) об'єктами.

- **Compact:** переміщує живі об'єкти впритул один до одного для усунення фрагментації.

### Покоління пам'яті (Generations):

**Gen 0:** короткоживучі об'єкти (локальні змінні, DTO). Очищується найчастіше і найшвидше.

**Gen 1:** буфер між Gen 0 та Gen 2 для об'єктів середньої тривалості життя.

**Gen 2:** довгоживучі об'єкти (Singleton, кеші). Збирання Gen 2 (Full GC) — найважче і викликає паузу (Stop-The-World).

**LOH (Large Object Heap):** об'єкти **> 85,000 байт** (великі масиви/буфери). За замовчуванням LOH не ущільнюється (ризик фрагментації пам'яті!).

**IDisposable vs Фіналізатор (~Destructor):**

`Dispose()` викликається розробником (детерміновано). Фіналізатор `~MyClass()` викликається GC у черзі *Finalizer Queue*, якщо об'єкт забули задіспозити (недетерміновано, об'єкт живе довше).

`GC.SuppressFinalize(this)` скасовує фіналізатор після успішного Dispose.

## Рівність у C# (Equality) & Пастка GetHashCode

### Способи перевірки рівності в C#:

**ReferenceEquals(a, b):**
Суворо перевіряє, чи вказують дві змінні на **одну й ту саму адресу в пам'яті** (Identity). Для Value Types завжди повертає `false` через boxing.

**Оператор == vs Equals():**
`==` — статичний оператор (для класів за замовчуванням порівнює посилання, але у `string` перевантажений для порівняння вмісту). `Equals()` — віртуальний метод `Object`, який можна перевизначити для порівняння за значенням полів.

**IEquatable<T>:**
Реалізація `bool Equals(T other)` забезпечує швидке порівняння без упаковки в `object` (відсутність Boxing для структур).

### Золоте правило співбесід: пастка GetHashCode():

**Контракт CLR:** Якщо два об'єкти рівні за `Equals()`, їхній `GetHashCode()` **ЗОБОВ'ЯЗАНИЙ повертати однакове число!**

**Що буде, якщо перевизначити Equals, але не GetHashCode?**

Об'єкт буде неможливо знайти в `Dictionary<TKey, TValue>` або `HashSet<T>`! Хеш-таблиця розрахує випадковий дефолтний хеш від адреси пам'яті, покладе об'єкт в один кошик (bucket), а при спробі знайти еквівалентний об'єкт шукатиме в іншому кошику і поверне `false` / `KeyNotFoundException`.
