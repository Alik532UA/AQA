> **Підтеми:** Сигнатура, overloading, ref, out, in, params, optional/named args, рекурсія

**Категорія:** C# Core & Advanced (.NET)

---

## Модифікатори параметрів: ref, out, in, params

За замовчуванням аргументи у C# передаються **за значенням (by value)**. Модифікатори дозволяють керувати способом передачі та пам'яттю:

**1. ref (Reference — двосторонній зв'язок):**
Змінна передається за посиланням. Змінна **зобов'язана бути ініціалізована** перед передачею. Метод може читати та змінювати її значення.

**2. out (Output — вихідний параметр):**
Змінна НЕ зобов'язана мати значення перед викликом, але викликаний метод **ЗОБОВ'ЯЗАНИЙ присвоїти їй значення** до свого завершення. Класичний приклад: `int.TryParse(str, out int val)`.

**3. in (Read-only reference, C# 7.2+):**
Передає великі структури (Value Types) за посиланням для оптимізації швидкодії, але **забороняє методу модифікувати** значення параметра.

**4. params (Змінна кількість аргументів):**
Дозволяє передавати аргументи через кому або готовий масив: `void AssertAll(params Action[] assertions)`. Має бути останнім у списку параметрів.

**Необов'язкові та іменовані параметри:**

`void Wait(int sec = 30, bool poll = true)` — дефолтні значення йдуть останніми.

Виклик: `Wait(poll: false)` — дозволяє пропускати перші аргументи за їх іменами.

## Перевантаження методів & Рекурсія

### Перевантаження методів (Method Overloading):

Оголошення методів з однаковим ім'ям, але **різною сигнатурою** (кількістю, типами або порядком параметрів).

**Важлива пастка інтерв'ю:** Зміна *тільки типу повернення* (наприклад, `int Foo()` та `void Foo()`) **НЕ є** перевантаженням і спричинить помилку компіляції. Сигнатура методу складається з імені та типів параметрів (з урахуванням `ref/out`).

### Області видимості змінних (Variable Scope):

- **Block Scope (фігурні дужки `{}`):** змінна доступна лише всередині блоку (циклу чи if).

- **Method Scope:** параметри та локальні змінні існують лише під час виконання стекового фрейму методу.

- **Class / Field Scope:** поля класу доступні всім його методам відповідно до модифікаторів доступу.

### Рекурсія та StackOverflowException:

Рекурсія — виклик методом самого себе. Вимагає обов'язкової **базової умови виходу (base case)**:

```
int Factorial(int n) {
    if (n <= 1) return 1; // Базовий випадок (умова виходу)
    return n * Factorial(n - 1); // Рекурсивний крок
}
```

**Небезпека:** Кожен рекурсивний виклик займає пам'ять у стеку (Call Stack). При безкінечній рекурсії або завеликій глибині виникає `StackOverflowException`, який аварійно зупиняє процес без можливості перехоплення у `catch`.
