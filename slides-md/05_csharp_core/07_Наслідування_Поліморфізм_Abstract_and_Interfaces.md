# Наслідування, Поліморфізм, Abstract & Interfaces

> **Підтеми:** : base, virtual, override, new, abstract class vs interface, явна та дефолтна реалізація

**Категорія:** C# Core & Advanced (.NET)

---

## Наслідування, : base & Поліморфізм (virtual/override)

### Наслідування (Inheritance):

Створення нових класів на основі існуючих. У C# підтримується **виключно одинарне наслідування класів** (але множинна реалізація інтерфейсів).

```
public class LoginPage : BasePage {
    // Виклик конструктора базового класу через : base(...)
    public LoginPage(IWebDriver driver) : base(driver) { }
    
    public override void Open() {
        base.Open(); // Виклик логіки базового методу
        NavigateTo("/login");
    }
}
```

### Поліморфізм: virtual, override та new:

**virtual / override (Динамічний поліморфізм):**
`virtual` у базовому класі дозволяє перевизначити метод. `override` у похідному класі змінює реалізацію. Виклик через базове посилання `BasePage page = new LoginPage(); page.Open();` викличе реалізацію `LoginPage` (через таблицю віртуальних методів vtable).

**new (Method Hiding — приховування):**
Розриває віртуальність. Якщо викликати метод через тип базового класу, виконається *базовий* метод; якщо через тип спадкоємця — новий прихований метод.

**sealed:** забороняє наслідування класу (`sealed class FinalPage`) або подальше перевизначення методу.

## Abstract Class vs Interface

### Порівняння Abstract Class та Interface:

Властивість
Abstract Class
Interface

Сутність
Відношення "IS-A" (є чимось)
Відношення "CAN-DO" (контракт поведінки)

Множинність
Лише одне наслідування
Клас може реалізувати безліч інтерфейсів

Поля та конструктори
Може мати поля екземпляра, стан та конструктори
Не може мати стану (полів) та конструкторів

### Явна та дефолтна реалізація інтерфейсів:

**Явна реалізація (Explicit Implementation):**
Вирішує колізію, коли два інтерфейси мають метод з однаковим ім'ям: `void IApiTest.Run() { ... }`. Метод доступний **тільки при приведенні об'єкта до відповідного інтерфейсу**: `((IApiTest)test).Run();`.

**Default Interface Methods (C# 8+):**
Інтерфейс може містити дефолтне тіло методу. Це дозволяє додавати методи в інтерфейс без ламання існуючих класів, що його реалізують.

**Порада для відповіді:** «Використовуйте абстрактний клас, коли потрібна спільна базова логіка та стан (наприклад, `BasePage` з полем WebDriver), та інтерфейси для забезпечення гнучкості та контрактів (`ILogger`, `IReportGenerator`)».
