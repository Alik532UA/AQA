# Test Automation Patterns

> **Підтеми:** Шаблони для автоматизації тестування

**Категорія:** Automation QA

---

## Шаблони проектування автотестів: POM, DDT, KDT

Шаблони тестування - це узагальнені рішення та найкращі практики, які вирішують типові проблеми дублювання, синхронізації та підтримки тестів.

### 1. Шаблон Page Object Model (POM):

- Розділяє тестовий код на дві частини: сторінки та самі тести.

- Кожна веб-сторінка представляється класом, що містить локатори елементів та методи взаємодії.

- Тестові кейси взаємодіють через бізнес-методи сторінки, що підвищує модульність та надійність.

### 2. Шаблон Data-Driven Testing (DDT):

- Використовує зовнішні джерела даних (CSV, JSON, Excel, DB) для параметризації тестів.

- Дозволяє багаторазово виконувати один тестовий сценарій з різними вхідними даними.

### 3. Шаблон Keyword-Driven Testing (KDT):

- Тести складаються з послідовності ключових слів (наприклад, Open, Login, Verify), що представляють конкретні дії.

---

## BDD та критерії вибору шаблону

### 4. Шаблон Behavior-Driven Development (BDD):

- Використовує природну мову для опису функціональності з точки зору користувача.

- Формат "Given-When-Then" (наприклад, Reqnroll / SpecFlow у .NET, Cucumber).

- Покращує комунікацію між розробниками, QA та бізнес-аналітиками.

### 5. Fluent Interface (Method Chaining):

Методи дій сторінки повертають екземпляр сторінки для створення зв'язних ланцюжків: `loginPage.EnterEmail().EnterPass().ClickSubmit();`

### Вибір шаблону тестування залежить від:

- **Складність проекту:** для простих завдань базовий POM, для складних — BDD або Screenplay.

- **Досвід команди:** вибір відповідних архітектурних шаблонів.

- **Вимоги до підтримки:** модульність для довгострокових проектів.

- **Частота змін:** легка адаптація до змін інтерфейсу.

Правильний вибір шаблонів підвищує підтримуваність та масштабованість фреймворку.
