# Platform Specific Test Automation

> **Підтеми:** Автоматизація для конкретної платформи (.NET)

**Категорія:** Automation QA

---

## Платформно-специфічна автоматизація тестування (.NET)

Підхід, коли тести створюються з урахуванням особливостей конкретної платформи: .NET Framework / .NET Core, ОС (Windows, Linux, macOS) та типу додатків (веб, десктоп, мобільні, API).

### Чому це важливо?

- **Глибоке покриття:** детальне тестування API, бібліотек та системних викликів платформи.

- **Точність та ефективність:** тести точніше виявляють дефекти і швидше виконуються.

- **Надійність:** стабільна робота компонентів у цільовому середовищі.

### Ключові аспекти:

- **Вибір інструментів:** NUnit, xUnit, MSTest, Selenium, Appium залежно від завдань.

- **Розуміння платформи:** знання внутрішніх механізмів .NET, асинхронності, пам'яті.

- **Написання тестів:** чітка модульна структура і повторюваність.

- **Інтеграція з CI/CD:** безперервний прогін та зворотний зв'язок.

---

## Приклади тестів для .NET та питання на співбесіді

### Приклади платформно-специфічних тестів для .NET:

- **Тестування веб-додатків:** Selenium WebDriver, Playwright for .NET для автоматизації браузера.

- **Тестування десктопних додатків:** UI Automation, FlaUI, WinAppDriver для десктопного інтерфейсу.

- **Тестування API:** RestSharp, HttpClient, Postman для тестування REST API.

- **Тестування баз даних:** Entity Framework Core, Dapper для прямої перевірки даних.

### Типові питання для співбесіди (Middle .NET QA):

- Які інструменти автоматизації тестування для .NET ви використовували?

- Розкажіть про свій досвід написання тестів для різних типів додатків (веб, десктоп, мобільні)?

- Як ви забезпечуєте підтримку і масштабування набору автоматизованих тестів?

- Які метрики ви використовуєте для оцінки ефективності автоматизованого тестування?
