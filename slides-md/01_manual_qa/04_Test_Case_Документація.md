# Test Case | Документація

> **Підтеми:** Check list, Bug / Error / Failure, Bug Report

**Категорія:** Manual QA

---

## Test Case | Тестовий сценарій

документ, що описує послідовність кроків для перевірки певної функціональності.

Action | Description | Expected Result | Test Result

Дія | Опис | Очікуваний результат | Результати тесту

Статуси: (passed | failed | blocked)

click on field e-mail | Login page is opened | Passed

### Ключові обов'язкові складові тест-кейсу:

- **PreConditions:** умови чи стан системи, необхідні для проведення перевірки.

- **Steps:** чітка послідовність дій для перевірки функціоналу.

- **Expected Result:** обов'язковий очікуваний результат згідно зі специфікацією.

- **PostConditions:** повернення системи у початковий вихідний стан (teardown/cleanup).

---

## Чек-лист (Checklist) | список перевірок

це документ, який описує, що повинно бути протестовано. Може бути абсолютно різного рівня деталізації залежно від вимог та складності продукту.

Як правило, чек-лист містить тільки дії (кроки) без надлишкового очікуваного результату.

Чек-лист менш формалізований, ніж тестовий сценарій. Його доречно використовувати в Agile, коли тест-кейси є надлишковими.

---

## Дефект / Error / Bug / Failure

**Error / Mistake (Помилка людини):**
дія людини (розробника, архітектора, тестувальника), що призводить до дефекту в коді чи документації. Також помилкова дія користувача (некоректне введення даних).

**Bug / Defect (Дефект / Баг):**
недолік або невідповідність у коді чи специфікації, створений внаслідок помилки людини, що спричиняє неправильну роботу системи.

**Failure (Збій / Відмова):**
подія під час виконання, коли система відхиляється від очікуваної роботи (краш, збій програми під час виконання).

---

## Баг Репорт (Bug Report)

це документ, що описує ситуацію або послідовність дій, яка призвела до некоректної роботи системи, із зазначенням причин і очікуваного результату.

### Структура баг-репорту:

**Заголовок / Шапка:**

- **Короткий опис (Summary):** Що? Де? Коли? (однозначно та стисло)

- **Проект (Project) & Компонент (Component)**

- **Номер версії (Version) & Автор (Author) & Призначено на (Assigned To)**

- **Серйозність (Severity):** S1 Blocker, S2 Critical, S3 Major, S4 Minor, S5 Trivial

- **Пріоритет (Priority):** P1 High, P2 Medium, P3 Low

- **Статус (Status):** Життєвий цикл дефекту (New, Open, In Progress, Resolved, Closed)

**Оточення (Environment):** ОС, Браузер + версія, Service Pack / версія ОС, роздільна здатність, пристрій.

**Опис (Description):**

- Кроки відтворення (Steps to Reproduce)

- Фактичний результат (Actual Result)

- Очікуваний результат (Expected Result)

- Прикріплені файли (Attachments: скріншоти, логи, відео)
